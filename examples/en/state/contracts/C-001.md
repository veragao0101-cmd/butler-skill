# C-001: tiny-todo HTTP API and page-serving contract

> Set by the butler, confirmed by the user on the API shape. Changing it needs the butler's approval. Referenced by T-001 (server) and T-002 (frontend).

## Todo object

`{ "id": number, "text": string, "done": boolean }`

## Endpoints (all JSON, `Content-Type: application/json`)

| Request | Success | Errors |
|---|---|---|
| `GET /api/todos` | 200 `[Todo, ...]` (empty list `[]`) | |
| `POST /api/todos` body `{"text":"..."}` | 201 `Todo` (done:false) | 400 `{"error":"..."}` for invalid JSON, missing/non-string/blank text |
| `POST /api/todos/:id/done` | 200 updated `Todo` | 400 `{"error"}` non-numeric id; 404 `{"error"}` unknown id |
| any other `/api/...` route or method | | 404 `{"error"}` (405 acceptable for wrong method on a known path) |

Error body is always `{"error": "<message>"}`.

## Page serving

- `GET /` returns `public/index.html` (`text/html; charset=utf-8`). That file is the whole frontend: a single self-contained file with inline CSS and JS, no external resources, no build step.
- The page calls the API with relative URLs (`/api/todos`, `/api/todos/<id>/done`), so it works on any host/port.
- Server: `PORT` env (default 3000); storage via the existing `TODO_FILE`.
